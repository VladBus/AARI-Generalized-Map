# AARI-Generalized-Map — автоматизация «Обобщёнки»

Автоматизация рассылки и размещения готовых результатов общей обзорной ледовой карты Арктики ААНИИ. Объединение слоёв и подготовка карт в QGIS остаются ручной работой эксперта.

## Что делает программа

- Проверяет ожидаемые имена файлов, наличие комплекта `.shp`, `.shx`, `.dbf`, `.prj` и грубое отклонение размера от эталонного выпуска.
- Размещает карты и SIGRID-наборы в согласованных сетевых каталогах.
- По средам готовит и отправляет пять писем по шаблонам `.eml` через SMTP (`email` + `smtplib`), не запуская Outlook или Thunderbird.
- По четвергам отправляет LVP и публикует материалы сайта с задержкой в одну неделю. Один двуязычный GIF копируется в обе папки `gif.en` и `gif.ru`.
- По средам в 15:00 отправляет коллегам статусный отчёт по адресу `AARI_REPORT_RECIPIENTS` из `.env`.
- В момент формирования отчёта создаёт папку следующей среды с каталогами `LVP`, `PIC`, `SHP`, `old_shore`, `sigrid`, `website`; существующие файлы и каталоги не удаляет.
- Пишет актуальную сводку в `STATUS.txt`, историю действий и ошибок — в `aari_generalized_map.log`. Оба файла находятся в корневой папке `ОБОБЩЕНКА_ОТПРАВКА`.

Исходные материалы не удаляются. Если целевой файл отличается от исходного, он заменяется, а факт замены записывается в журнал. Резервные копии не создаются. Очевидно подозрительный размер или отсутствующий компонент блокирует соответствующее задание и попадает в статус и лог.

## Подготовка окружения и настройка `.env`

Все команды выполняются в терминале PowerShell VS Code из папки проекта:

```powershell
cd E:\Programming_Work\VScode_Work\AARI-Generalized-Map
git pull

if (-not (Test-Path ".venv\Scripts\python.exe")) {
    py -m venv .venv
}
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

if (-not (Test-Path ".env")) {
    Copy-Item .env.example .env
}
notepad .env
```

`git pull` обновляет Python-файлы до последнего коммита. Если `.env` уже существует, команда его не перезаписывает. `.env` — локальный файл конфигурации; его не добавлять в Git и не присылать вместе с паролем.

### Переменные `.env`

| Переменная | Назначение |
|---|---|
| `AARI_SOURCE_ROOT` | Корень исходных выпусков `\\10.31.34.60\Tiris\МОРЕ\ОБОБЩЕНКА_ОТПРАВКА` |
| `AARI_MORE_ROOT` | Каталог `МОРЕ` для общей BMP и двух PNG |
| `AARI_ICE_CHARTS_ROOT` | Корень `\\files.aari.ru\Ice_charts` |
| `AARI_MORSPASS_ROOT`, `AARI_SOVBEZ_ROOT` | Целевые каталоги morspass и sovbez |
| `AARI_ICECHARTS_V_ROOT` | UNC-путь, соответствующий `V:\IceCharts` |
| `AARI_LVP_WAVE_ROOT` | UNC-путь, соответствующий `Z:\LVP_WAVE` |
| `AARI_WEBSITE_ROOT` | Корень сайта `\\data.aari.ru\d0015\arctic` |
| `AARI_SMTP_SERVER`, `AARI_SMTP_PORT` | SMTP-сервер и порт; по умолчанию `zmail.aari.ru` и `465` |
| `AARI_EMAIL_ADDRESS` | Учётная запись отправителя |
| `AARI_EMAIL_NAME` | Отображаемое имя отправителя, необязательно |
| `AARI_EMAIL_PASSWORD` | Пароль учётной записи отправителя |
| `AARI_REPORT_RECIPIENTS` | Получатели еженедельного отчёта, разделённые запятыми или `;` |
| `AARI_SIZE_MIN_RATIO`, `AARI_SIZE_MAX_RATIO` | Допустимое отношение размера к эталону; по умолчанию `0.35` и `2.5` |

Заполни реальные `AARI_EMAIL_ADDRESS` и `AARI_EMAIL_PASSWORD`. Список отчёта можно редактировать прямо в `.env`, например:

```dotenv
AARI_REPORT_RECIPIENTS=vvbusev@aari.ru,a.sokolov@aari.ru,sanovikov@aari.ru
```

Оставь сетевые пути из `.env.example`, если они совпадают с доступными каталогами на рабочем компьютере. Не запускай отправку через SMTP, пока не проверены адреса в пяти шаблонах и настройки аккаунта.

## Безопасная проверка перед рабочим запуском

**На этом этапе не запускать `install_task.ps1` и не добавлять параметр `--execute`.** По умолчанию программа работает в режиме `dry-run`: она проверяет источники и формирует план, но не копирует продуктовые файлы и не отправляет письма. Для журнала и `STATUS.txt` запись всё равно выполняется в `AARI_SOURCE_ROOT`.

### 1. Запустить unit-тесты

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Все тесты должны завершиться с `OK`. Если есть `FAIL` или `ERROR`, не переходи к следующим шагам — скопируй полный вывод терминала.

### 2. Проверить комплект текущего выпуска

Для демонстрационного выпуска за среду 21 октября 2026 года:

```powershell
.\.venv\Scripts\python.exe .\main.py --stage validate --date 2026-10-21
```

Команда проверяет ожидаемые исходные файлы и размеры без копирования. Для другого выпуска замени `2026-10-21` на дату его папки в `ОБОБЩЕНКА_ОТПРАВКА`.

### 3. Просмотреть весь план среды и пять писем

```powershell
.\.venv\Scripts\python.exe .\main.py --stage wednesday --date 2026-10-21
```

Без `--execute` файлы не копируются, письма не отправляются. В терминале появятся точные пути источников и назначения, ошибки проверки файлов, а для писем — темы, адресаты и список вложений. Если источники отсутствуют, ошибки ожидаемы; сверяй их с фактической структурой выпуска.

### 4. Просмотреть четверговые копии и публикацию сайта

```powershell
.\.venv\Scripts\python.exe .\main.py --stage thursday --date 2026-10-22
```

Команда в безопасном режиме проверит план LVP и публикацию набора `website` за предыдущую неделю, не копируя сами файлы.

### 5. Просмотреть еженедельный отчёт

```powershell
.\.venv\Scripts\python.exe .\main.py --stage report --date 2026-10-21
```

В режиме `dry-run` папка следующей недели не создаётся, отчёт не отправляется. Проверяется формирование отчёта и список `AARI_REPORT_RECIPIENTS`.

После проверок открой в исходном корне `STATUS.txt` и `aari_generalized_map.log`. `STATUS.txt` накапливает результаты всех этапов текущего выпуска (проверка, среда, четверг и отчёт), включая источники, точные назначения, почтовые темы, адресатов и пути вложений. После перехода к следующему выпуску сводка начинает формироваться заново. `aari_generalized_map.log` хранит хронологию запусков, копирования, замен, почтовых событий и ошибок. Сначала согласуй статус и список получателей отчёта; реальное копирование, SMTP-отправку и установку расписания проверяем отдельным этапом.


## Планировщик заданий Windows

В проекте один файл запуска — `run_aari_generalized_map.bat` — и одна задача планировщика. Установщик `install_task.ps1` регистрирует задачу `AARI-Generalized-Map` с четырьмя триггерами; все они вызывают тот же BAT:

| День | Окно повторных проверок | Назначение |
|---|---|---|
| Среда | 11:00–11:50, каждые 5 минут | Выгрузка `old_shore` до 12:00 |
| Среда | 14:00–14:50, каждые 5 минут | Основные файлы; повторная проверка `old_shore`; пять продуктовых писем — только при финальном запуске |
| Среда | 15:00 один раз в неделю | Отчёт коллегам и создание каталога следующего выпуска |
| Четверг | 14:00–14:50, каждые 5 минут | LVP и материалы сайта за прошлую неделю |

Окна оставляют время до соответствующих сроков, а повторные короткие запуски позволяют подхватить файлы, появившиеся позже. В среду каждый запуск с 14:00 по 14:50 повторно проверяет и `old_shore`, поэтому поздно подготовленные файлы также будут выгружены до окончания окна. На промежуточных запусках обновляются только файлы; пять продуктовых писем не отправляются до финального запуска в 14:50. В 15:00 отдельный триггер формирует отчёт из последнего `STATUS.txt` и отправляет его списку `AARI_REPORT_RECIPIENTS`. Тогда же создаётся папка следующего выпуска с шестью пустыми подпапками; уже существующие каталоги не очищаются. Параллельные экземпляры запрещены. Задача использует текущую учётную запись Windows и рассчитана на запуск, когда пользователь вошёл в систему и сетевые ресурсы доступны.

Установить или обновить задачу после переноса проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\install_task.ps1
```

## Важные соглашения

- Дата папки выпуска — среда; дата карты в именах — вторник (`YYYYMMDD`). На картинках период указывается как воскресенье–вторник, например `18-20 октября 2026 года`.
- `STATUS.txt` содержит результаты этапов текущего выпуска с деталями по каждому файлу и почтовому вложению. `aari_generalized_map.log` хранит историю всех запусков, успешных операций, замен, отправок и ошибок.
- Программа не объединяет и не исправляет геоданные в QGIS.
- Перед реальной отправкой и публикацией необходимо подтвердить пути и адресатов на тестовом выпуске.

## English summary

Windows automation for distributing already-prepared AARI Arctic overview chart products. It validates expected files and approximate sizes, copies products to configured UNC shares, sends five `.eml`-based messages over SMTP, and publishes the previous week's website products on Thursday. QGIS compilation remains manual. It uses one batch launcher, one scheduled task, and two shared operational reports.
